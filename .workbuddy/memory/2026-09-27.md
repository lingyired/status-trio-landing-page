## 修「滚一会儿就滚不动」（01:0x）

ling：「为何我往下滚的时候，滚一会儿就不会继续滚了」。根因 = 上一轮加内部滚动兜底时顺手
写了 `overscroll-behavior: contain`：面板浮在视口上方、滚轮大概率悬在它上面 → 面板一成
可滚容器，滚轮先喂它，contain 在面板滚到头后掐断滚动链 → 整页停住。修复 = 只删
`overscroll-behavior: contain` 这一行（`.sp` 保留 max-height + overflow-y，面板到头自动
接力整页）。`.cl-panel`（更新日志模态框）的 contain 正常保留。tsc ✓ build ✓，grep 产物
确认 .sp 无 contain、`.cl-panel` 那份还在。教训已写进 LAYOUT.md 第 15 条。

## 修「面板滚到截图区就跟丢了」（01:2x，真凶抓到）

ling 第二次报「大概到『菜单栏、程序坞，同一个图标。』下面，它就不会继续往下了」——「它」=
面板：sticky 中途失效，滚过约一屏面板就被推出视口。

**根因（headless 探针实测定位）**：`.lp-desktop` 是横排 flex（justify-content:center），
`.lp-column` 作为 flex item 默认 `align-items: stretch` → 列盒子被拉伸到**视口高**（748px），
8400px 的内容全是溢出；滚动不受影响（scrollHeight 算溢出后代），但 **sticky 的活动范围 =
包含块盒子** = 那个 748px → 面板钉满一屏就被列底边推走。旧浮动面板时代 JS 逐帧重摆位置
掩盖了这个隐患，改纯 CSS sticky 后暴露。

**修复**：`.lp-column { align-self: flex-start }`（列盒子高度 = 内容高度），一行。
实测：colBottom 0→8404，panelViewportTop 在 scrollTop 0…7500 恒定 46，滚到底 7636 面板仍钉着；
agent-browser 真浏览器截图 /tmp/verify-pin-{1400,4500}.png 双确认。

**探针基建**：托管 node 工作区已有 playwright（`/Users/lingsmbp/.workbuddy/binaries/node/
workspace/node_modules`，chromium 缓存在 ~/Library/Caches/ms-playwright），`NODE_PATH=… node
scroll-probe*.mjs` 可直接量几何；agent-browser 在同目录 .bin 下（无 resize 命令，eval +
scroll + screenshot 够用）。探针脚本留在工作区：scroll-probe{,2,3,4,5,6}.mjs。
