## Product changes

- Current release metadata now uses `v1.8.0`, build `46`, `15.5 MB`, the
  `StatusTrio-1.8.0.dmg` URL, and SHA-256
  `8f5f64b36a95d3e552a8fe2a3a25cce0c1746d332cdcaef2a688cc53bc94e334`.
- The release-note snapshot workflow now excludes drafts and prereleases. The
  generated changelog contains 19 published releases, beginning with `v1.8.0`
  and including `v1.7.5`.
- Added a reusable Homebrew command component in Hero and the installation
  section. It copies exactly `brew install --cask status-trio`, reports success
  or truthful clipboard failure, and never executes an installation.
- Mirrors retain their existing URLs and download reporting. Chinese copy now
  clearly labels 1.8.0 mirror availability as unverified.
- The `MIRRORS` source comment no longer claims the cloud-drive links contain
  the same DMG as GitHub. It explicitly requires manual version verification
  before release.
- Battery settings now expose charger input, battery charging power, system
  power, optional fixed CPU-energy examples, a 10-60 second example interval,
  and the optional Charge to Full action. Native defaults are preserved:
  charger input off; battery and system power on; CPU examples off at 10
  seconds; Charge to Full preference on.
- Battery power-flow examples derive from the selected power source in both
  Settings and Battery Details. On battery, no external-flow values appear;
  charging shows `67 W / 42 W / 21 W`; connected-but-not-charging shows
  `67 W / 0 W / 21 W`. CPU-activity fallback examples carry `%` units.
- Battery Details shows example power metrics and bounded flow rails while
  connected to power, up to five fixed CPU-energy examples, and a reversible
  page-only Charge to Full flow with private-API/macOS/hardware caveats.
- Charge simulation keeps the simulated limit separate from the battery
  reading. Start requires a connected source and `<100%`; completion advances
  the example to 100% on power; cancel and restore preserve the reading/source
  at that moment; explicit reset restores the pre-start snapshot. Hiding the
  demo or unplugging terminates the active phase without retaining background
  state.
- The bilingual Charge to Full note preserves the native caveat that after a
  full charge or reconnecting power, the limit may remain at 100% until it is
  cancelled or restored in System Settings, and restoring it does not lower the
  current battery level.
- Audio settings now demonstrate Standard/DDC versus BetterDisplay, running or
  unavailable integration state, and automatic or manual display association.
  A shared `activeVolumeSource` resolver gives native writable volume priority,
  enables Standard/DDC, selects the BetterDisplay route when available, and
  disables output volume/mute controls in both Settings and Status Panel when
  unavailable. External configuration is editable only for the display example.
  Manual association status uses the selected display, and DDC-only guidance is
  limited to the Standard/DDC route. The website never launches BetterDisplay or
  inspects audio hardware.
- Bluetooth settings add an explicit Apple devices/battery opt-in with fixed
  examples and 1.7.5 pairing-prompt/retry guidance. The status panel shows fixed
  Apple device rows only when enabled.
- Existing eight settings categories and order, status-panel visibility/order,
  persistent detail route, connected controls, responsive layouts, and both
  complete Chinese and English language surfaces are retained.
- Mobile troubleshooting grids now use zero-minimum tracks so the long
  Gatekeeper checksum scrolls only inside its copyable pill instead of widening
  and clipping the help section at 375px and 390px in English.
- Feature introductions describe native battery power flow, CPU energy impact,
  and BetterDisplay external-display volume support. Fixed-example and
  browser-only limits remain in the interactive demo explanations.
